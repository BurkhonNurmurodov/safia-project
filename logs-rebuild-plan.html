Logs page rebuild

The Logs page gives most of its width to three columns of navigation and most of its height to numbers that repeat each other, then clips the one column that says what changed. This plan replaces the shell with one sidebar, turns the category list into a filter, and gives the table the room it needs. The dark navy and gold, the copy, and the data stay. Those parts already work.

Diagnosis

What a first-time user sees

In the first five seconds: three columns of links, four boxes that all say 5 626, and a table whose last column runs off the screen. They work out that this is a log. They cannot tell which column of links to use, and they cannot read what changed without expanding a row. The page promises “who did it, when, and what changed” and delivers the first two.

Keep these

Dark navy with one gold accentDistinctive and calm for an eight-hour screen. Nothing in this plan changes the palette.
The copy“Plan override set”, “Signed in via Telegram”, “Worker concern filed” read as sentences. The action phrases need no rewriting.
The dataTime to the second, actor with role, category, action, target, outcome. The new page needs nothing added to the model, only a before/after payload for the detail panel.
Category counts and ⌘KBoth exist already. They move, they do not get rebuilt.

Issues, ordered by user impact

Critical

Three navigation columns before any content

The outer sidebar is about 330px wide and holds one item, “Admin”. The section sidebar and the category list add roughly 540px more. The table gets what is left and clips its last column.

The Target column is cut off at the viewport edge on every row, and the actual change is only reachable by expanding each row with an unlabeled chevron.

Quick wins: one day, no redesign

These ship on the current code and remove the most embarrassing defects while the rebuild is in progress.

  1. Give the sticky table header an opaque background and a z-index. The bleed-through disappears.
  2. Delete the KPI subtitles, or shorten them to fit: “of 5 626”, “today”, “Akhmedova M.” Nothing in a card may end in an ellipsis.
  3. Hide zero-count categories behind a “Show 5 empty” link.
  4. Show role as a muted suffix on the same line as the name. Rows drop from about 60px to 44px.
  5. Use one date format everywhere: “3 Nov 2026”.
  6. Collapse the outer “Admin” sidebar to a 56px icon rail by default. The table gains about 270px.

Target design

One sidebar, one filter bar, one stat line, one table. Nothing on the page repeats a number or a label that appears elsewhere. The accent appears once in navigation and once in the table (the selected row). Shown in Inter as a stand-in; keep whatever typeface the app uses today. A working prototype on mock data implements everything below: filters, the category menu, the detail panel, keyboard navigation and each state.

How the layout works

  • Sidebar, 240px. Brand row with “SAFIA IMS · Admin” and a collapse control. Three groups as today. Items 34px tall, 6px radius, icon 16px in the muted colour. Selected item: gold text on gold at 12% opacity. Collapses to a 64px icon rail with tooltips; the state is remembered per user.
  • Top bar, 56px. ⌘K search at 360px on the left. On the right: notifications (dot when unread), language, theme, help, then the user. No page title here; the sidebar already says where you are.
  • Page header. “Logs” at 24px/600 and a one-line description at 15px in the secondary colour. Nothing else. Export lives in the toolbar, next to the filters it exports.
  • Filter bar, 36px controls, 8px gaps. Search grows to 440px. Each filter button shows its name and its value (“Category · All”). Export sits at the far right as a secondary button. When any filter is not at its default, a row of removable chips appears under the bar and the export label reads “Export 2 152 rows”.
  • Stat line, 13px. Events, people, refused chip, live indicator. 16px above, 12px below. It is the only summary on the page.
  • Table. Full content width (1136px at 1440). 40px header, 44px rows, 1px dividers, hover in surface-2, selected row with a 2px gold left stripe. Fits six columns at 1280px; Category hides first below that, then Role. Footer shows position and a “Load 100 more” link, with infinite scroll as the primary mechanism.

Category becomes a filter

The 250px sidebar becomes a 320px menu that opens from the Category button. Same counts, same names, no truncation, and it costs no width when closed.

What changed lives in a detail panel

Clicking a row opens a 440px panel over the right edge. It is not modal: the table stays visible and ↑ ↓ moves through events while it is open.

Table body at 14px rather than 16px is deliberate: this is a scanning surface used all day, not reading content, and 16px would cost four rows per screen. Everything outside the table that is meant to be read is 15px or larger. Time and all counts use font-variant-numeric: tabular-nums.

Components and behavior

Filter bar

  • Search matches who, action and target. Debounced at 250ms. / focuses it from anywhere on the page; ⌘K stays global.
  • Time range defaults to Today. Presets: Today, Yesterday, Last 7 days, Last 30 days, Custom (two date fields, one format). The button shows the chosen label, or “3–9 Nov” for custom.
  • Category is the menu above. Multi-select, immediate apply, counts reflect the other active filters.
  • Outcome is Any, Allowed, Refused. The “6 refused” chip sets it to Refused.
  • Role is Any, Admin, Supervisor, Leader, System.
  • Every filter writes to the URL (?from=2026-11-03&to=2026-11-03&category=shop-floor&outcome=refused&q=olcha). Back and forward work. A pasted link opens the same view. This is the single most useful thing an audit log can do for a team.
  • Export CSV exports the filtered set, and its label carries the count. Over 10 000 rows it asks the user to narrow the range or confirm.

Rows and the detail panel

  • The whole row is the click target. No chevron column. Cursor changes to pointer and the row lifts to surface-2 on hover.
  • Click, or Enter on a focused row, opens the panel for that event. The row gets the gold stripe and stays highlighted until the panel closes.
  • The panel is 440px, overlays the right edge, and is not modal. ↑ ↓ move to the previous or next event; Esc closes it and returns focus to the row. It slides in over 200ms, or fades when the user prefers reduced motion.
  • Panel contents: category eyebrow, action, outcome chip; who (links to the profile), when (absolute and relative), target (links to the entity); what changed as old → new pairs; context (source, IP, event id with a copy-link button). Refused events add a “Why” line.
  • Refused rows carry a 2px danger stripe on the left and the chip after the action. The row text does not change colour.

Accessibility

  • A real <table> with th scope="col" and a visually hidden caption: “Audit log, 5 626 events on 3 November 2026”.
  • Rows are focusable (tabindex="0") and announce as buttons that open the event. The panel has role="complementary" and an aria-label with the action and time.
  • Category icons in the sidebar are aria-hidden; every item has visible text.
  • Focus ring on everything: 2px gold, 2px offset. Never removed.
  • Outcome is never colour alone: the refused chip carries the word and the icon.

Open questions for the team

None of these block phase 0 or phase 1. Phase 2 needs answers to the first two.

  1. What is “Action history”, and how is it different from Logs? If it is the same data scoped to the current user, it becomes a “Me” filter on the audit log and the nav item goes. If it is something else (an undo stack, for instance), it needs a name that says so.
  2. What does the tilde in “~olcha-u” denote? A cell, a line, a workstation? The target column and the panel should name the entity type, and the panel should link to it.
  3. Should the default range be today or the last 24 hours? A factory with night shifts is better served by a rolling 24 hours; a calendar day splits a shift across two views.
  4. Is the outer “Admin” sidebar a workspace switcher? If supervisors and leaders see other entries there, it becomes a switcher in the brand row. If “Admin” is the only entry for admins, it goes.
  5. Volume. 5 626 events in one day is about two million a year. The table needs server-side filtering, cursor pagination and search; the export needs a size limit. Confirm the API can filter by all five dimensions before phase 2 starts.
